# COBOL Account Management Test Plan

Use this plan to validate the current COBOL behavior with business stakeholders and as a basis for unit and integration tests in the Node.js application. Unless a case says otherwise, start a fresh application run so the in-memory balance begins at `1000.00`. Enter amounts with two decimal places. Record observed output in **Actual Result**, then set **Status (Pass/Fail)**.

| Test Case ID | Test Case Description | Pre-conditions | Test Steps | Expected Result | Actual Result | Status (Pass/Fail) | Comments |
|---|---|---|---|---|---|---|---|
| TC-001 | Initialize a new account balance | Application is not running. | Start the application and select **View Balance**. | The initial balance is `1000.00`. The menu is available again after viewing. |  |  | Confirms the initial value set by `DataProgram`. |
| TC-002 | View the balance without changing it | Fresh application run; balance is `1000.00`. | Select **View Balance** twice. | Both displays show `1000.00`; viewing does not change the balance. |  |  | |
| TC-003 | Credit a fractional amount | Fresh application run; balance is `1000.00`. | Select **Credit Account**; enter `0.01`; then select **View Balance**. | The credit succeeds, displays a new balance of `1000.01`, and a later view shows `1000.01`. |  |  | Checks two-decimal amount handling and read-after-write. |
| TC-004 | Credit a whole amount | Fresh application run; balance is `1000.00`. | Select **Credit Account**; enter `250.00`; then select **View Balance**. | The credit succeeds and the balance becomes `1250.00`. |  |  | |
| TC-005 | Accumulate multiple credits | Fresh application run; balance is `1000.00`. | Credit `10.25`, then credit `4.75`, then view the balance. | Both credits succeed and the final balance is `1015.00`. |  |  | Confirms each operation uses the latest stored balance. |
| TC-006 | Debit a fractional amount | Fresh application run; balance is `1000.00`. | Select **Debit Account**; enter `0.01`; then select **View Balance**. | The debit succeeds and the balance becomes `999.99`. |  |  | |
| TC-007 | Debit an amount less than the balance | Fresh application run; balance is `1000.00`. | Select **Debit Account**; enter `250.00`; then select **View Balance**. | The debit succeeds and the balance becomes `750.00`. |  |  | |
| TC-008 | Debit the exact available balance | Fresh application run; balance is `1000.00`. | Select **Debit Account**; enter `1000.00`; then select **View Balance**. | The debit is allowed because the balance equals the requested amount; the new balance is `0.00`. |  |  | Confirms the comparison is greater-than-or-equal. |
| TC-009 | Reject a debit greater than the balance | Fresh application run; balance is `1000.00`. | Select **Debit Account**; enter `1000.01`; then select **View Balance**. | The application displays the insufficient-funds message and the balance remains `1000.00`. |  |  | Confirms a rejected debit does not write a changed balance. |
| TC-010 | Debit zero | Fresh application run; balance is `1000.00`. | Select **Debit Account**; enter `0.00`; then select **View Balance**. | The current logic accepts the debit because the balance is at least zero, displays a successful debit, and leaves the balance at `1000.00`. |  |  | Stakeholders should confirm whether zero-value transactions should be accepted. |
| TC-011 | Credit zero | Fresh application run; balance is `1000.00`. | Select **Credit Account**; enter `0.00`; then select **View Balance**. | The credit flow completes and the balance remains `1000.00`. |  |  | Stakeholders should confirm whether zero-value transactions should be accepted. |
| TC-012 | Select an unsupported numeric menu option | Application is at the menu. | Enter `5`; when the menu returns, select **View Balance**. | An invalid-choice message is displayed; the application continues to the menu. Viewing the balance still shows the unchanged balance. |  |  | Also check `0` as another unsupported numeric choice. |
| TC-013 | Exit the application | Application is at the menu. | Enter `4`. | The menu loop ends and the application displays the goodbye message. |  |  | |
| TC-014 | Verify balance lifetime across runs | Complete a credit or debit so the balance differs from `1000.00`; exit the application. | Start the application again and select **View Balance**. | The new run starts at `1000.00`; the previous run's balance is not persisted. |  |  | Confirms storage is in memory only. |
| TC-015 | Check the maximum representable balance | Fresh application run; balance is `1000.00`. | Credit `998999.99`; view the balance. | The amount and resulting balance are within the declared `PIC 9(6)V99` capacity; the resulting balance is `999999.99`. |  |  | |
| TC-016 | Attempt a credit that exceeds the balance field capacity | Fresh application run; balance is `1000.00`. | Credit `999000.00`; observe the credit response, then view the balance. | The Node.js application rejects the credit with a maximum-balance message; the balance remains `1000.00`. |  |  | The balance field capacity is `999999.99`; reject overflow rather than relying on runtime-specific COBOL behavior. |
| TC-017 | Enter an amount with more than two fractional digits | Fresh application run; balance is `1000.00`. | Select **Credit Account** and enter `1.239`; observe the result and view the balance. | The Node.js application rejects the amount and leaves the balance unchanged; it does not round or truncate. |  |  | Amounts accept at most two fractional digits. |
| TC-018 | Enter malformed or out-of-range amount input | Fresh application run; balance is `1000.00`. | Try a nonnumeric amount and an amount with more than six integer digits in separate runs. | The Node.js application rejects each amount, displays an error, returns to the menu, and leaves the balance unchanged. |  |  | Amounts must be non-negative and no greater than `999999.99`. |
| TC-019 | Enter nonnumeric menu input | Application is at the menu. | Enter letters instead of a numeric menu choice. | The Node.js application displays an invalid-choice message, returns to the menu, and does not change the balance. |  |  | The COBOL numeric input conversion/runtime behavior may vary; the Node.js application explicitly rejects nonnumeric menu input. |
| TC-020 | Confirm a failed debit leaves the balance available for later operations | Fresh application run; balance is `1000.00`. | Attempt to debit `1000.01`; then credit `10.00`; then view the balance. | The debit is rejected without changing the balance; the subsequent credit succeeds, and the final balance is `1010.00`. |  |  | Covers the insufficient-funds branch followed by a successful transaction. |
